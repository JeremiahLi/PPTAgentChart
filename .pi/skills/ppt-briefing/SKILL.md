# 汇报型（briefing）

**本仓库目前的默认呈现效果就是汇报型。** 受众是决策者：他们只看这一份材料，
不会去翻原文。目标：**每页一个主张，第一眼就能看懂结论。**

配套的公共规范在 `ppt-common`（出图通道 / 14 版式契约 / 图标 / 通用铁律），
机检规则在 `.pi/renderer/briefs/briefing.yaml`（**只有 `check` 段，很短，扫一眼即可**；
写作规范以本文件为准）。开工前读三样：`ppt-common`、`.pi/renderer/briefs/briefing.yaml`、
`.pi/skills/ppt-common/examples-all.json`。**别每生成一页就去读一个范例文件。**

## 取舍规则（与研讨型的分界线）

可以**对原文做总结与抽象**——但结论必须有原文数据支撑，且不因为抽象而失真。

**必须做到**

- 每页标题写成一句**主张**（"资源应继续向县域倾斜"），不要写成话题（"渠道概况"）
- 每页一个主张；支撑它的证据**不超过 3 条**
- **结论先行**：最重要的结论放最前面
- 关键数字要单独突出，不要埋在段落里
- 加粗只标关键词（`**...**`，每处 ≤16 字）：每页**重点** 1-2 处；
  卡内的 `**关键短语**：` 是骨架、不占这个配额 —— 渲染器不会自动加粗，
  整句加粗等于没加粗
- 页面别留大片空白：字段写到接近安全上限，表格行少就补行或写 `note`
- **卡片要有骨架**：长文本（statement 正文卡 / `numbered_cards.desc`）标 2~3 处
  `**关键短语**：正文…`（短语加粗染成强调色，冒号后正文接着排，与正文**同字号**
  —— 放大字号会把文字顶出卡片背景）；`statement.body` 用换行分卡、每卡**第一句**
  自动加粗染色成关键句（≤48 字、写成判断）。纯文字卡因此也能"扫短语就读懂"
- **卡片标题即重点**：图表装不下的内容用卡片承载时（`numbered_cards`），
  `name` 写成**判断句/带数字的结论**（「统一任务集管理」），别写名词短语
  （「任务集管理」）；标题已是判断句就把 `sub` 省掉 —— `--qc` 会点名名词式标题
- **一页两块内容 → 左右分置**：用 `panel_2col`（两个模块，各自背景框 +
  顶部总结陈述段），或表格配 `side`、图表配右侧洞察；不要上下堆叠留出半页空白
- **内容太少就并页**：表格 < 5 行、图表数据点 ≤ 4 且无明细表、`panel_2col` 单侧
  要点 < 3 条，或 `--qc` 报"还空 X in"，就把相邻页同主题的内容并进来
  （两块原本分属两页 → 并成一页左右并排）

**不要**

- 把正文精简过头：抽象 ≠ 抽干。`statement.body` ≥ 150 字、compare 每栏 desc ≥ 45、
  numbered_cards 每卡 desc ≥ 40、layered_stack 每层 desc ≥ 30、flow 每步 desc ≥ 16、
  hierarchy 每个 node.desc ≥ 20 —— 低于下限 `--qc` 会点名"精简过头"
- 堆砌细节——细节留给人问、留给附录
- 把原文的限定条件抽象掉（"试点三省存活率 94%"不能写成"存活率 94%"）
- 在标题里用"情况介绍 / 相关说明 / 概述"这类无信息量的词
- 整句/大段加粗，或者同一个内容块里画两个图标

## 输入分析（排页之前必须先做）

读完全部输入后，先按 `ppt-common` 工作流第 0 步做一次结构化分析并落 `.pi/work/analysis.md`：
**章节 → 模块 → 核心结论（一句主张）→ 论据（数字·口径）→ 缺口**。
写完**直接排大纲**，只在大纲环节让用户过目一次。

汇报型比研讨型更能抽象：一个模块可以压成一页、多个同类模块可以合并成一页，
但**每条主张都要能在分析表的论据列里找到出处**，关键数字与限定条件不得失真。
分析表"缺口"列有内容的，页面上要留一句显式占位（`note` / `footer_note` / 表格补一行
「待补」），写清缺什么、找谁要。

## 结论段（summary）

标题下那段结论段同样是硬指标（见 `ppt-common`）：**40~80 字、2~3 句**，
禁章节坐标与「本节/原文/见表」、禁填充语、不复述标题。汇报型的结论段尤其要
**开口就是主张**，把关键数字放在第一句里，机制细节下放到卡片/栏描述。

## 页数

**不设上限**。页数由资料量决定；排完大纲后如果**预计超过 30 页**，把这件事
**并进大纲评审那一次**问完（只讲某几章？拆成多份？还是转研讨型？）——
慢档只在那里打断一次，出图后不再另开一轮。别为了"控制在 12 页内"把内容砍掉 ——
密度不够时该做的是并页 + 写满，不是删主张。

## 落地

```bash
# 一条命令：合并 + 质检 + 渲染 + 字体自检（外观两参数可选，不写就是 style-harness + flat）
python .pi/renderer/build.py .pi/work/slides -o .pi/out/主题.pptx --title 标题 \
    --brief briefing --style blue-business --card outline
# 改完页先看红线（不落盘）：把 -o 那段换成 --check
```

汇报型默认建议 `blue-business` 或 `style-harness` 配色 + `outline`/`accent-top` 卡片：
对决策者说话时，克制的色调比多色更容易被当成结论而不是装饰。选型表见 `ppt-common`。

`build.py` 的质检会按 `.pi/renderer/briefs/briefing.yaml` 的 `check` 段查红线并报 warning：
页数下限与"超 30 页先问用户"、每页支撑论据上限、标题禁用词。**warning 不是可选项**，
那是这个方向的取舍约定（**但页数没有上限：不许靠删内容压页数**）。

## 大纲模板

```
01 cover       封面
02 toc         目录（>6 页就要有）
03..NN         每页 = 一个主张 + 最多 3 条证据（statement / chart / compare_3col / table）
...            页数由资料量决定；预计超过 30 页先问用户
NN end         结尾
```
