# 研讨型（seminar）

受众是**会对着这份材料逐条讨论的同事**。目标：把输入资料的内容
**无遗漏**地呈现在页面上，**不替读者做取舍**。

配套的公共规范在 `ppt-common`（出图通道 / 14 版式契约 / 图标 / 通用铁律），
机检规则在 `.pi/renderer/briefs/seminar.yaml`（**只有 `check` 段，很短，扫一眼即可**；
写作规范以本文件为准，不要在两个文件里重复读同一段话）。开工前读三样：
`ppt-common`、`.pi/renderer/briefs/seminar.yaml`、`.pi/skills/ppt-common/examples-all.json`。
**别每生成一页就去读一个范例文件** —— 那是 40 页 deck 白搭 40 次读盘与上下文。

## 铁律一：资料的论点论据全部上页，一条不丢

这是研讨型与汇报型最根本的分界。汇报型可以抽象、可以砍，研讨型**不能**——
原文说了什么就摆什么。原文里的具体数字、口径、限定条件必须原样保留。

**做法（别跳过这一步）**：

1. **先抽清单，落 `.pi/work/analysis.md`**：按 `ppt-common` 工作流第 0 步的模板，
   把资料拆成 **章节 → 模块 → 核心结论 → 论据（数字·口径·限定条件）→ 缺口**。
   一行一个模块，不许合并；清单**随大纲一起**给用户过目（不必单独停下来等确认）。
2. **再排页**：给清单里每一项分配落点（哪一页、哪个版式、哪个字段）。
   一个论点放不下就**拆页**，不要合并后不说明。
3. **收尾核对**：排完页回头过一遍清单，确认**每一项都有落点**。
   有落点=有编号写在某页的某个字段里。对不上的补页。

**允许优化到哪一步**（研讨型的边界）：

- ✅ **允许改写措辞**：把原文的长段落压成一句判断句、合并同类表述、删掉重复的过渡句；
  标题下那段 `summary` 更要重写精炼（40~80 字、2~3 句，禁章节坐标与废话；
  只留「判断 + 关键数字」，机制细节下放到卡片，页头是每页最贵的一块版面）。
- ❌ **不许丢论据**：论据条目一条都不能少，原文的数字、口径、限定条件原样保留。
  改完逐条回 `analysis.md` 的论据列核对，少一条就补回去。
- ❌ **不许把正文压成短语**："精炼"是改写措辞，不是删掉机制与数字。
  每类版式的正文字数下限见铁律三 —— 低于下限就是精简过头，`--qc` 会点名。

**禁止**：

- 用"显著提升""大幅改善"这类没有数字的形容词替换原文数字
- 丢掉限定条件（"试点三省存活率 94%"不能写成"存活率 94%"）
- 为了版式好看而删内容——**放不下是拆页，不是删**

### 铁律一的机检：`--source .pi/work/analysis.md`

**丢内容是最难被抓到的偷懒方式**：版面装不下 → 删掉两页 → 质检全绿（页内检查
看不出"整块内容没进 deck"）。所以交稿前**必须**带上输入分析跑一次：

```bash
python .pi/renderer/build.py .pi/work/slides -o .pi/out/主题.pptx \
    --brief seminar --source .pi/work/analysis.md
```

外观（配色 `--style` / 卡片 `--card`）与这一条无关，按 `ppt-common` 的表自选；
研讨型资料密度高，`outline`（透明底、轻）或 `accent-left`（清单感）通常比默认白卡更耐看。

它按两个口径交叉核对，把"没进 deck"的内容点出来（都是 warning，需要你逐条核对）：
1. **数字口径**：analysis.md 里带 %/单位、或 3 位以上的指标数字，deck 全文找不到的；
2. **模块名**：analysis.md 表格里的模块名，其 4-gram 在 deck 里一个都不出现的；
3. 另外报「论据行数 ÷ 内容页数」——平均每页要扛 6 条以上，说明页数明显偏少。

被点到的内容**只有两种处理方式**：落到页面上，或确认已被别处覆盖（改写措辞、
写成中文数字、模块合并）。**不许为了压页数删掉** —— 缺的就加页。

### 版式容量不是"删内容的理由"

各版式的条目上限（`flow 3–12 步`、`layered_stack 3–12 层`、`numbered_cards 4–8 张`、
`hierarchy 2–8 个`、`compare_3col 3–4 栏`、`table ≤12 行`…）只约束**一页能摆多少**，
不约束"总共能讲多少"：**超了就另起一页继续**（`schema` 报错信息里已经写明这条）。
上限本身也已按真实几何容量放宽 —— **文档里有几层就写几层、有几项就写几项**：
层数多渲染器自动压紧条形与间距，卡数多自动排成 4 列（窄卡不再画图标把宽度让给文字），
`flow` 超过 6 步自动排成两行折返（7~12 步一页装下）。**没有一个上限需要靠删内容去满足。**

## 铁律二：尽量每页都有图表、表格

研讨型是**看图说话**的材料，不是念稿。默认每个内容页都应该是图示页，
`statement`（纯文字页）只留给"结论 + 论证"的总结页，**占内容页不超过四分之一**
（2026-09 由「三分之一」收紧到「四分之一」）。

**版式路由（按内容形态选，别偷懒用卡片堆）**

| 资料长这样 | 用哪个版式 |
|---|---|
| 数值、占比、趋势、多组对比 | `chart`（柱/条/折线/饼/环/雷达） |
| 明细数据、参数对照、口径表、逐条清单 | `table` |
| 有先后顺序、阶段、生命周期、管道、决策链路 | `flow`（迭代闭环必须写 `loop_note`） |
| 包含/拆分/层级、递进/升级/阶梯 | `hierarchy`（contain / progressive） |
| 多方案对比、三种口径对照 | `compare_3col` |
| 4~6 个并列要点 | `numbered_cards` |
| 底层支撑上层的依赖关系 | `layered_stack` |
| 一页要放**两块内容**（各带要点或迷你明细表） | `panel_2col`（左右两个模块，各一个背景框 + 顶部总结段） |
| 结论 + 论证 + 关键数据 | `statement`（带 `highlight`） |

**"各种"图表**：图型要换着用——同一份 deck 里至少出现 **3 种不同图型**
（`column` / `bar` / `line` / `pie` / `doughnut` / `radar`），别整份都是柱状图。
饼/环图只能 1 个系列。

**如果某段资料实在没有可图表化的数据**：用 `table` 把它结构化（哪怕两列：
条目 + 说明），也比整段文字强。表格是研讨型最可靠的兜底版式。

## 铁律三：每页铺满，但靠"补内容"而不是"拉排版"

研讨型的每一页都要**占满版面**，半页空白 = 资料没铺完。**但留白不许用拉高行高、
拉长卡片来硬撑**（那样只会得到一张松垮的表格），正确做法是：

1. **把下一章节 / 关联章节的内容并到本页**：表格加行、卡片加要点、并页。
   上一页没排完的明细、同一主题的后续论述，都可以并进来。写到接近安全上限为止；
2. **两块内容一律左右分置，不许上下堆叠**：一页要放两块内容时用 `panel_2col`
   （左右两个模块，各一个背景框 + 顶部总结陈述段），或表格加 `side`、图表配右侧洞察。
   上下堆叠几乎必然在下半页留下半页空白；
3. **内容太少就并页**：表格 < 5 行、图表数据点 ≤ 4 且补不出明细表、`panel_2col`
   单侧要点 < 3 条，或 `--qc` 报"还空 X in"→ 先把相邻页同主题的明细并进来；
   两块内容原本分属两页就**并成一页左右并排**（`panel_2col`）；
4. **原文确实没有对应资料** → **显式占位**：表里补一行（首列「待补」，写明缺什么、
   找谁要），或写 `note` / `footer_note`。空白必须变成一句看得见的缺口说明；
5. 一页讲不完就**拆页**，拆页的成本远小于"页面下半截空着"。

**卡片要有骨架（关键句 + 关键短语）**：纯文字卡最容易写成一坨段落 —— 观众扫不到重点，
整页显得"没有特点"。骨架**不靠放大字号**（放大 + 加线会把文字顶出卡片背景），
统一是「**同字号 + 加粗 + 强调色**」：
① `statement.body` 用**换行分卡**（≤3 张），每张卡的**第一句会被自动加粗染色**
   成关键句，所以第一句要写成判断句且 **≤48 字**；
② 卡内长文本（>170 字）标 **2~3 处关键短语**：`**判定口径**：…`「**反例**：…」——
   渲染器把短语加粗染成强调色，**冒号后的正文在同一段里接着排**（不另起行、不占额外高度）。
`--qc` 点名「关键句太长」与「长文只有 N 处关键短语」。

**卡片标题即重点**：图表装不下的内容用卡片承载时，卡片的**加粗标题本身就是重点**——
写成判断句或带数字的结论（「统一任务集管理」「回归通过率 62%→88%」），
不要写名词短语（「任务集管理」「能力建设」）；标题已是判断句就把 `sub` 省掉。
`--qc` 会点名名词式标题。

**放不下是渲染器的事**：正文/描述/单元格会自动逐档降字号（最低 10pt），
`--qc` 只在"降到最小档仍放不下"时才点名 —— 所以**写满比写短安全**，
不要为了"怕溢出"把论据压成短语。真写不下该做的是并页/拆页，不是删字。

**正文不许精简过头**：高密度 = 单位版面信息多，不是字少。`statement.body` ≥ 150 字、
compare 每栏 desc ≥ 45、numbered_cards 每卡 desc ≥ 40、layered_stack 每层 desc ≥ 30、
flow 每步 desc ≥ 16、hierarchy 每个 node.desc ≥ 20 —— 改写润色可以，
把论据/机制/口径压成短语就是抽干信息，`--qc` 会逐页点名。

`--qc` 会给每个表格页算出「只占多少 / 还空多少 / 大约还能放几行」，
照着这个数字加行或补占位，别当噪音忽略。

**加粗只标关键词**（见 `ppt-common`）：每处 ≤16 字，每页**重点** 1-2 处。
`statement.body` 必须用 `**...**` 标出核心短语——渲染器不会自动加粗，
不标这一页就没有重点，`--qc` 会提示。
注意卡内的 `**关键短语**：` 是**骨架**、不算重点配额（长卡要求 ≥2 处）——
"每页 1-2 处"说的是额外的重点标注，两者不冲突。

## 页数：由资料量决定，不设上限

**研讨型没有页数上限**——资料有多少就摆多少，宁可多一页，不要合并后不说明。
正文页数 ≈ 论点论据清单的规模。

**唯一的例外**：抽完清单、排完大纲后，如果**预计超过 50 页**，在**大纲评审那一次**
一并问用户：只讲某几章 / 拆成多份 / 转汇报型。问完就往下做 ——
慢档只有大纲评审这一次打断，出图后不要再开一轮问答。不要闷头生成 50 页再交付。

**反过来的错误同样严重：为了"显得紧凑"把总页数压下来。**
页数少不等于密度高 —— 密度是**单位版面信息多**（每页铺满、图表化、两个信息块），
不是页数少。以下都是踩过的坑：

- ❌ 版式装不下（步数/条目超上限）→ 删掉几步 → 内容没了。**正确做法：另起一页继续**
  （`flow` 7~12 步已支持两行折返，不用拆也不用删）。
- ❌ 觉得"页数太多"→ 合并相邻页 → 每页塞成麻花 / 或干脆少讲一块。**正确做法：保持页数，
  把每页做扎实**（补论据、补第二块信息、图表化）。
- ❌ 交稿前不跑 `--source` 核对 → 少了几块内容自己也不知道。**正确做法：见铁律一的机检**。

## 结论段要按研讨型的标准写

每个内容页标题下的那段 `summary`，是研讨会上最先被念出来的一句话，必须：

- **开口即结论**，带原文的**数字或口径**（研讨型最忌空泛的判断）；
- **不写章节坐标**：「1.2 节给出四条驱动力」「这是原文自带的对比表（2.1 节）」
  「研讨时建议逐条确认」——坐标与阅读指引是讲稿里说的，不是页面上的字；
- **不复述标题**：标题说了判断，结论段接着讲依据、边界与待确认点。

五条硬指标（40~80 字 / 2~3 句 / 禁坐标词 / 禁填充语 / 不复述标题）见 `ppt-common`，
`--qc` 会逐条点名，回炉时只改被点名的那一页。

## 缺口显式占位

资料里缺什么模块，就在页面上明写缺什么、要向谁要哪份材料。
没有现成版式就用 `footer_note` 写一句，例如
`footer_note: "本章缺 2024 年渠道数据，需向市场部索取后再补一页"`。
**不许用"待补充"含糊过去**——写清缺的是哪份、找谁要。

## 落地

```bash
# 一条命令：合并 + 质检 + 渲染 + 字体自检（--style/--card 可选，不写就是 style-harness + flat）
python .pi/renderer/build.py .pi/work/slides -o .pi/out/主题.pptx --title 标题 \
    --brief seminar --style violet-tech --card accent-left --source .pi/work/analysis.md
```

质检会按 `.pi/renderer/briefs/seminar.yaml` 的 `check` 段查红线并报 warning：
资料量对应的页数、表格/图表占比、图表种类数、必备版式。**warning 不是可选项。**
`--source .pi/work/analysis.md` 再核一遍**输入覆盖度**（丢了哪块内容、少了哪个数字）——
研讨型交稿前这一项必须过，见铁律一。

## 大纲模板

```
01  cover       封面
02  toc         目录（按资料章节，不要重排）
03  section     第一章
04..NN          第一章的每一节 = 每个论点一页（chart / table / flow / hierarchy 优先）
...             逐章铺下去，一章都不漏
NN  end         结尾 + 缺口清单（哪几项还缺材料、找谁要）
```
